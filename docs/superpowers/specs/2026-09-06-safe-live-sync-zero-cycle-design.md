# 안전한 자동 동기화와 제로관리 회차 표시 설계

## 목표

여러 컴퓨터에서 동시에 작업해도 조용히 데이터를 덮어쓰지 않게 하고, 다른 사용자의 변경을 약 2초 안에 자동 반영한다. 제로관리 일정은 현재 작업본의 등록·수정·이동·체크·삭제 개선을 유지하면서 메모와 선택형 회차 정보를 달력과 목록에서 작게 확인할 수 있게 한다. 재고현황에서도 현재 로그인 분류의 약품 마스터를 추가하거나 제외할 수 있게 한다.

## 제약

- 기존 Cloudflare Pages, Pages Functions, D1만 사용한다. 별도 유료 실시간 서비스나 Durable Object, WebSocket 서버를 추가하지 않는다.
- 사용량 `dailyUsage`는 계속 메모리에만 유지하고 서버나 localStorage에 저장하지 않는다.
- `(전주기)`, `(다음주기)`, `치료 완료`를 포함하여 사용자가 요구하지 않은 상태 문구를 추가하지 않는다.
- 기존 미커밋 변경을 보존하고 `public/index.html`과 `항암제_재고관리.html`의 배포본·백업본 동작을 일치시킨다.
- 같은 항목에 대한 동시 변경은 자동으로 덮어쓰지 않는다.

## 선택한 접근

현재 `app_state.updated_at` 값을 서버 버전으로 사용한다. 별도 테이블이나 유료 서비스 없이 조건부 갱신을 수행한다. 클라이언트는 마지막으로 동기화한 스냅샷과 버전을 보관하고 저장 요청에 `base_updated_at`을 포함한다.

서버는 현재 버전과 `base_updated_at`이 일치할 때만 `UPDATE ... WHERE updated_at = ?`를 실행한다. 영향을 받은 행이 없으면 HTTP 409와 최신 상태를 반환한다. 이 조건부 갱신은 두 요청이 같은 이전 버전에서 출발했을 때 하나만 성공하게 하므로 마지막 전체 JSON 저장이 이전 변경을 조용히 지우는 문제를 막는다. 기존 버전이 없는 저장 요청은 HTTP 428로 새로고침을 요구해 오래 열린 구버전 탭의 무조건 덮어쓰기도 차단한다.

## 자동 병합과 충돌

클라이언트는 `기준 스냅샷`, `내 상태`, `서버 최신 상태`를 비교하는 3방향 병합을 사용한다.

- 한쪽에서만 바뀐 최상위 필드는 바뀐 값을 사용한다.
- `zeroDrugs`는 `id`, `drugMaster`와 `generalDrugMaster`는 `code` 단위로 비교한다.
- 서로 다른 환자 일정이나 서로 다른 약품 마스터를 고친 경우 두 변경을 합친다.
- 한 사용자가 삭제하고 다른 사용자가 같은 항목을 수정한 경우를 포함하여 같은 항목이 양쪽에서 다르게 바뀌면 충돌로 처리한다.
- 다른 배열이나 객체는 최상위 필드 단위로 비교한다. 양쪽이 같은 필드를 다르게 바꿨다면 안전을 위해 충돌로 처리한다.
- `daily_data`는 날짜 키 단위로 병합한다. 같은 날짜가 양쪽에서 다르게 바뀌면 충돌로 처리한다.

충돌이 없으면 최신 버전을 기준으로 자동 재저장한다. 충돌이 있으면 해당 항목 이름을 알리고 자동 저장을 중단한다. 서버 최신 데이터를 적용해 화면을 다시 그리며, 사용자는 최신 내용을 확인한 뒤 필요한 변경을 다시 수행한다. 로컬의 충돌 변경을 자동으로 강제 덮어쓰는 버튼은 만들지 않는다.

## 자동 반영

로그인 상태에서 2초마다 현재 버전을 확인한다. GET 요청에 `since`를 보내고 변경이 없으면 서버는 304를 반환하여 큰 JSON 본문을 전송하지 않는다. 브라우저 탭이 다시 보이거나 창이 포커스를 받을 때도 즉시 확인한다.

서버가 바뀌었고 로컬에 저장 대기나 저장 진행이 없으면 최신 상태를 적용하고 현재 탭을 다시 렌더링한다. 사용자가 input, select, textarea 또는 인라인 수정 폼을 편집 중이면 적용을 잠시 보류하고 포커스가 빠진 직후 반영한다. 저장 중에는 중복 요청을 직렬화하고, 저장 도중 추가 변경이 생기면 현재 요청 완료 후 한 번 더 저장한다.

동기화 배지는 `동기화 중`, 마지막 반영 시각, `다른 사용자 변경 충돌`만 간결하게 보여준다.

## 제로관리 일정

현재 작업본에 있는 다음 동작을 유지하고 테스트한다.

- 새 환자·약품 일정 등록과 기존 일정 삭제
- 시작일, 주기, 처방량, Day 구성 수정
- 달력에서 현재 일정 전체 또는 개별 Day 이동
- 달력과 목록에서 투여 체크 및 취소
- `(전주기)`와 `(다음주기)` 문구 미표시
- 동일 환자·동일 약품명이 있어도 일정 `id`로 정확한 항목을 체크

### 선택형 회차

각 제로관리 일정에 다음 선택 필드를 추가한다.

- `cycleCurrent`: 현재 회차의 양의 정수
- `cycleTotal`: 전체 회차의 양의 정수

두 값이 모두 유효하고 `cycleCurrent <= cycleTotal`일 때만 `3/6` 형식으로 표시한다. 기존 데이터와 입력하지 않은 일정에는 아무 문구도 표시하지 않는다.

등록 폼과 인라인 수정 폼에서 두 값을 쉽게 입력·변경·삭제할 수 있다. 일정 이동은 회차를 바꾸지 않는다. 현재 주기의 마지막 Day가 체크되어 다음 주기로 자동 전환되면 `cycleCurrent`를 1 올린다. 미래 주기를 직접 체크하여 여러 주기를 건너뛰면 건너뛴 주기 수만큼 올린다.

현재 회차가 전체 회차에 도달한 뒤 그 회차의 마지막 Day가 완료되면 이후 미래 주기 일정을 생성하지 않는다. 해당 일정이나 기존 투여 기록을 삭제하지 않으며 별도의 상태 문구도 표시하지 않는다. 사용자가 회차 값을 수정하거나 전체 회차를 비우면 다시 그 값에 맞춰 미래 일정이 계산된다.

회차 배지는 환자 목록의 약품 요약 옆과 달력의 환자 일정 안에 작은 중립색 텍스트로 표시한다. 셀과 행의 높이를 불필요하게 늘리지 않는다.

### 메모

환자 카드의 이름 바로 아래에 `memo` 본문을 한 줄로 항상 표시한다. 접두 문구를 붙이지 않고, 메모가 없으면 공간을 만들지 않는다. 긴 메모는 말줄임표로 줄이고 제목 속성으로 전체 내용을 확인할 수 있게 한다. 한 줄을 클릭하면 기존 메모 편집 영역이 열리고 저장할 수 있다. 달력 셀에는 메모를 반복 표시하지 않아 공간을 보존한다.

## 재고현황의 마스터 편집

재고현황 카드 상단에 작은 `마스터 편집` 버튼을 둔다. 버튼을 누르면 한 줄짜리 검색·추가 영역이 열린다.

- 현재 업로드된 재고에서 코드 또는 약품명으로 검색하고 선택하면 현재 로그인 분류의 마스터에 추가한다.
- 이미 등록된 항목은 중복 추가하지 않는다.
- 재고 표의 각 행에는 관리자에게만 보이는 작은 제외 버튼을 둔다.
- 제외는 재고 원본이나 일별 스냅샷을 삭제하지 않고 현재 분류의 마스터에서만 제거한다.
- 추가·제외 직후 재고현황, 사용량/잉여, 대시보드, 제로관리 약품 선택 목록을 다시 그린다.

## 오류 처리

- 네트워크 실패 시 현재 화면 상태를 유지하고 동기화 실패 배지를 표시한다. 다음 자동 확인 또는 사용자 변경 때 재시도한다.
- 409 충돌은 일반 네트워크 오류와 구분하여 사용자에게 충돌 항목을 알린다.
- 잘못된 회차 입력은 저장하지 않고 짧은 오류 알림을 보여준다. 현재 회차와 전체 회차 중 하나만 입력한 경우도 미입력으로 처리하지 않고 두 값을 모두 입력하도록 안내한다.
- 자동 반영으로 `dailyUsage`, 현재 폼 입력값, 정렬 상태, 조회 기간 같은 세션 전용 UI 상태를 지우지 않는다.

## 검증

- Functions 단위 테스트에서 조건부 저장 성공, 오래된 버전의 409, `since`가 같은 GET의 304를 검증한다.
- 순수 병합 함수 테스트에서 서로 다른 일정 자동 병합, 같은 일정 수정 충돌, 삭제 대 수정 충돌, 서로 다른 마스터 병합, 같은 날짜 `daily_data` 충돌을 검증한다.
- 제로관리 테스트에서 회차 입력 검증, 자동 증가, 여러 회차 건너뛰기, 마지막 회차 이후 미래 일정 중단, 수동 수정, 달력·목록 표시를 검증한다.
- 기존 제로관리 회귀 테스트로 등록·수정·이동·체크·삭제 및 금지 문구 미표시를 확인한다.
- 재고현황 마스터 테스트에서 추가·중복 방지·제외와 재고 원본 보존을 검증한다.
- 전체 Node 테스트와 두 HTML 파일의 핵심 스크립트 일치 검사를 실행한다.

## 배포 범위

구현과 로컬 검증까지만 수행한다. 실제 Cloudflare Pages 배포는 사용자가 별도로 요청하거나 승인한 경우에만 실행한다.
